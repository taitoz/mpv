# mpv portable configuration

## Project goals and user intent

- Build a portable Windows mpv configuration for the widest possible video compatibility, maximum practical image quality and full use of NVIDIA/AMD hardware decoding and GPU processing. Hardware support is device/codec/driver dependent; do not promise universal acceleration. AMD compatibility is a goal, not yet verified on this PC.
- Baseline VR mode is a clean VR-to-flat preview for manually tuning restoration. Do not automatically add restoration/upscaling/denoising/sharpening shaders to baseline VR. The reprojection shader itself is necessary and explicitly allowed; "without shaders" means without additional enhancement shaders.
- Intended workflow: inspect flat preview, manually choose restoration/color/deband/shader parameters, reproduce them in a playback command, then process and capture/export the result. Distinguish flat one-eye preview from restoration/export of the complete original stereoscopic SBS/TB frame.
- The user's sample restoration chain is nlmeans → FSRCNNX_x2_16-0-4-1_enhance → adaptive-sharpen → SSimDownscaler, with manually selected color/scaling/deband options and conditional auto-profiles disabled. It is an example, not a universal preset.
- User reports that their full mpv rawvideo/NUT → FFmpeg scale_cuda + hevc_nvenc command was tested and the restoration effect is present in the output. Treat this as the working baseline, not an untested proposal. Topaz and Real Video Enhancer were too slow for the user's needs. Confirmed by test: `--glsl-shaders` and vo settings are NOT exported via `--o` (rawvideo stays source-size). Working GPU export path is `--vf=gpu=w=<out>:h=<out>` — offscreen vo_gpu filter that applies the same `--glsl-shaders`; FSRCNNX WHEN requires output >1.4x source in BOTH dims (verified: 3400x1700 → 4096x2048 output is byte-identical with/without FSRCNNX; active at 4800x2400). SSimDownscaler is inactive when upscaling. FFmpeg's implicit RGB→NV12 uses BT.601 untagged — always use `scale=out_color_matrix=bt709:out_range=tv` and bt709/tv output tags. `tools/vr-ab-test.bat [1|2|3|nl] [seconds]` (cmd.exe only): baseline is pure FFmpeg CUDA decode → scale_cuda → NVENC; shader variants render at final size via vf=gpu → NUT pipe → BT.709 NV12 → NVENC (no second scaling); `nl` = nlmeans-only diagnostic. The home PC (i5-11400F, RTX 3070, Seasonic GX-1000) suffers Kernel-Power 41 hard reboots without WHEA during exports; the hardware debug plan is in `tools/hardware_and_system_configuration_guide.md` section 9. Plan a separate AMD encoding path; CUDA/NVENC are NVIDIA-specific.
- Final delivery target: complete stereoscopic VR video served through XBVR and played in DeoVR on Meta Quest 2. Preserve projection, both eyes/layout, fps, audio sync and relevant metadata; flat preview is only for tuning. Judge success by in-headset quality, smooth playback, bitrate/network feasibility and processing throughput.
- Next experiment: compare source, scale+encode only, matching output with FSRCNNX, and the full chain. Hold output resolution/fps/encoder settings constant across processed variants; record speed, size/bitrate and temporal artifacts in the headset. Check redundant scaling and eye-boundary filtering. Prefer moderate source-specific presets; QP 18 is not a universal optimum. Do not switch to slower models without demonstrated benefit.
- Installer delivery intent: `tools/bootstrap.ps1` remains a temporary/test downloader for provisioning verification environments, not the final product installer. The chosen first-public-release model is Inno Setup or an equivalent compiled installer containing our config and a dependency-detection wizard, WITHOUT bundling third-party binaries or automatically downloading them. Detect mpv/ffmpeg/ffprobe in the selected directory and PATH, support manual paths, validate startup/features, and show trusted source links/manual installation instructions plus a retry button. mpv is required; missing ffprobe (metadata VR detection) or ffmpeg (export) should allow playback-only installation with explicit limitations. Resolve manual provisioning/detection of uosc/ziggy separately; do not silently bundle it. Preserve mpv.exe beside portable_config, user settings, backups and rollback. User PATH integration should be an explicit option; never change Machine PATH.
- Public-release licensing scope: exclude film-grain, evafast, reload, ytsub, cycle-commands and custom-scripts unless provenance/license verification clears them; establish whether custom-scripts is user-authored before excluding it. Remove their references/options/bindings alongside package exclusion and test the remaining config. Preserve notices and ship required license texts for remaining scripts/shaders/resources; update THIRD_PARTY.md. Do not bundle personal fonts. External/manual binary installation reduces redistribution scope but does not waive config component licenses. These exclusions are PLANNED, not completed.
- Installer CI/CD plan: GitHub Actions checks on PR/push; prepare a clean allowlisted release staging tree without runtime/personal files or third-party binaries; check required files, license notices and excluded-component references. On version tag or manual dispatch, use pinned build tools on a Windows runner to build one installer EXE, smoke-test installation/uninstallation in isolation without changing the working environment, then publish the EXE, SHA-256 and version/commit details in GitHub Releases. Keep installer source/workflows in the repo. CI-only verification dependencies are not release payload. Authenticode signing is a separate future task pending provider/certificate selection; do not claim signed releases exist. Real NVIDIA/AMD GPU, shader, VR and export validation remains separate from generic hosted CI. The compiled installer and workflow are NOT implemented yet; do not conflate this roadmap with current bootstrap behavior.
- Future work: research VSR activation for playback. `tools/bootstrap.ps1` implements an x64 Windows portable installer/updater using direct GitHub releases (mpv MSVC, Gyan FFmpeg, version-matched uosc helper), SHA-256 asset verification, commit-pinned config with Git blob verification, conflict preservation, backups and rollback. GPU/media compatibility still requires a playback smoke test.
- `README.md` contains the Russian user-facing goals, current behavior, controls, sample restoration command, export caveats, verification instructions and roadmap. Keep it consistent with implementation.

Own files carry SPDX GPL-3.0-or-later headers with copyright "taitoz". `THIRD_PARTY.md` inventories bundled components and licenses; items marked unverified (evafast, reload, ytsub, cycle-commands, custom-scripts, film-grain) must not be treated as freely redistributable until checked. ## Current implementation and verification

- Git repository root is `portable_config`; origin is `git@github.com:taitoz/mpv.git`. `.gitignore` excludes runtime cache/history/watch-later state, backups/logs/temp files, media/output files, executable dependencies and personal NetflixSans/TX-02 fonts. Keep configs/scripts/shaders and uosc font resources eligible for versioning. The ignored ziggy-windows.exe dependency must be supplied separately when installing a clone. Audit third-party licenses before publication; preserve generic paths in README examples.
- Bootstrap runtime pitfalls: the upstream MSVC `mpv.exe` is a GUI executable; use `Diagnostics.Process` with explicit exit waiting, output capture and timeout instead of relying on PowerShell `$LASTEXITCODE`. Lua probes need `--idle=yes` and an explicit script-triggered quit; `--idle=no` with no media can exit before Lua executes. All bootstrap mpv validation uses `Invoke-MpvCheck` with `--media-controls=no`: the v0.41.0 MSVC build intermittently hangs on shutdown after successful Lua quit with Windows SMTC enabled (reproduced; 30 repeated probes passed with SMTC disabled). This flag must not change normal playback configuration. `bootstrap-tests.ps1 -MpvExecutable '<staged-mpv.exe>'` runs 30 real Lua probes plus config parsing without installing anything. Gyan FFmpeg 9.0.2 enumerates `scale_cuda`, `hevc_nvenc` and `hevc_amf`; actual GPU encoding remains hardware/driver dependent.
- Bootstrap verification: offline tests and a real isolated install/rollback passed with mpv v0.41.0 MSVC, Gyan FFmpeg 9.0.2 and uosc 5.13.0. No GPU/media playback was tested through the bootstrapper. `tools/bootstrap-tests.ps1` runs dependency-free offline tests on Windows PowerShell 5.1; `tools/bootstrap.ps1 -Destination '<player-dir>' -PlanOnly` checks live release/config discovery without writing files. Execution policy may require explicit user approval for a process-only bypass; never change persistent policy automatically. The installer always fetches committed remote config, not local uncommitted edits. After successful installation/update, bootstrap adds the player directory to persistent User PATH without duplicates; Machine PATH is never changed. `-NoPath` disables this, `-PlanOnly` never writes PATH, and rollback leaves PATH unchanged. PATH update errors warn without undoing installed files. Tests cover PATH string merging without changing registry settings. Existing terminals/IDEs need restart; generated `launch.cmd` still provides process-local helper PATH. State/staging/backups are beside portable_config under `.bootstrap`; upstream-removed files remain, and modified config conflicts require manual merging.
- Player executable: `G:\Downloads\mpv\mpv.exe` (PowerShell invocation requires `&`).
- `mpv.conf` includes `profiles.conf` and `vr_profiles.conf`.
- Screenshot format is PNG: the current mpv build fails to open its WebP encoder, whereas PNG was verified via IPC screenshot-to-file. Use Ctrl+S (`screenshot window`) to capture GPU VR reprojection; ordinary video screenshots do not capture the shader result.
- VR preview uses `gpu-next`, `gpu-api=d3d11`, `hwdec=d3d11va` and `shaders/vr-flat.glsl`; do not introduce CPU `v360` or hardware-download filters for this path.
- `scripts/vr-detect.lua` defers the `on_load` hook while asynchronously probing local files with ffprobe (10-second timeout). It sets `user-data/vr-profile` before playback: metadata takes priority, filename patterns are fallback, `none` means ordinary video. VR auto-detection is restricted to `.mp4` filenames (case-insensitive); all other extensions set `none` without invoking ffprobe. Remote inputs are not probed. Options `vr-detect-ffprobe` and `vr-detect-timeout` can be passed via `--script-opts`.
- Resolution-based quality profiles must require `user-data/vr-profile == none` because they clear `glsl-shaders`. VR profile conditions use the same property, not filenames directly.
- Detection reads Spherical Mapping/Stereo 3D stream side data and tags `projection`/`vr_projection`, `stereo_mode`/`stereo_layout`, `vr_fov`/`id_fov`. Unsupported spherical rotation/crop or projection falls back to filenames. Fisheye metadata requires SBS and explicit 190/200-degree FOV. Do not infer VR from resolution alone.
- Filename fallback recognizes delimited `3dv`/`OU`/`TB` as vertical stereo and `3dh`/`SBS` as horizontal stereo, combined with 180/360 projection markers. The three user-provided 180_3dv, 360_OU and 180_180x180_3dh_LR files have no VR metadata; all three were smoke-tested together with correct profile transitions and d3d11va decoding.
- `scripts/vr-look.lua` activates Alt+left-button drag and Ctrl+Backspace reset only while `vr-flat.glsl` is loaded. It updates `vr_yaw` and `vr_pitch` while preserving the other native `glsl-shader-opts` entries; `change-list ... set` replaces the entire parameter map.
- Shader parameter `vr_projection`: 0 = half-equirectangular 180, 1 = equirectangular 360, 2 = equidistant fisheye. `vr_stereo_tb`: 0 = first SBS eye, 1 = top TB eye, 2 = mono.
- Smoke test with a user-provided local video: `& 'G:\Downloads\mpv\mpv.exe' '<video-path>' --frames=5 --no-audio --keep-open=no --autocreate-playlist=no --watch-later-options= --save-position-on-quit=no --msg-level=vo/gpu-next=debug`. Check hardware decoding, shader compilation and absence of filter errors; this opens a playback window briefly.
