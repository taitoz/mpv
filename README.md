# mpv portable config

Переносимая конфигурация mpv для Windows: качественное воспроизведение обычного и VR-видео с максимально возможным использованием аппаратного декодирования и GPU-обработки NVIDIA и AMD.

## Цель проекта

- Поддерживать максимально широкий набор форматов, кодеков, разрешений и типов видео.
- Задействовать возможности GPU для максимального качества с приемлемой плавностью и минимальной лишней нагрузкой на CPU.
- Обеспечить переносимость: mpv и весь конфиг находятся рядом, без обязательной глобальной установки.
- Для VR предоставлять чистое flat-превью для ручного подбора параметров реставрации.
- Развить воспроизводимый процесс: просмотр исходника → настройка фильтров и шейдеров → проверка результата → обработка и сохранение нового видео.

Это цели, а не гарантия аппаратной поддержки любого кодека на любой видеокарте. Доступные режимы зависят от модели GPU, драйвера, разрядности, цветовой субдискретизации и сборки mpv/FFmpeg. Если аппаратный декодер не поддерживает источник, потребуется программное декодирование.

## Структура

```text
mpv/
├── mpv.exe
└── portable_config/
    ├── mpv.conf                  Основные настройки
    ├── input.conf                Клавиши и мышь
    ├── profiles.conf             Профили качества и аудио
    ├── vr_profiles.conf          GPU-перепроекция VR → flat
    ├── vr_rst.conf               Экспериментальный профиль реставрации
    ├── vr_vsr.conf               Экспериментальный профиль VSR
    ├── scripts/
    │   ├── vr-detect.lua          ffprobe и выбор VR-профиля
    │   └── vr-look.lua            Управление направлением взгляда
    ├── shaders/
    │   └── vr-flat.glsl           Шейдер перепроекции
    ├── script-opts/
    ├── fonts/
    └── cache/
```

Показаны основные файлы, а не полный список. `~~/` в настройках mpv указывает на каталог конфигурации.

## Требования и запуск

- mpv для Windows с `gpu-next` и поддержкой нужного аппаратного декодера.
- Актуальный совместимый драйвер NVIDIA или AMD.
- `ffprobe` в `PATH` для определения VR по метаданным.
- `ffmpeg` для исследования источников и будущего процесса экспорта.

Из каталога с mpv, в `cmd.exe`:

```cmd
mpv "X:\Path\To\Video.mp4"
```

В PowerShell путь к программе запускается через `&`; пути с символом `$` удобнее заключать в одинарные кавычки.

## Текущее состояние аппаратного воспроизведения

- Обычное видео: `vo=gpu-next`, `gpu-api=vulkan`, `hwdec=vulkan`.
- Автоматические профили качества выбирают масштабирование и дополнительные шейдеры для обычного видео.
- VR: `vo=gpu-next`, `gpu-api=d3d11`, `hwdec=d3d11va` и GPU-перепроекция.
- На текущем ПК проверено аппаратное воспроизведение на NVIDIA GeForce RTX 3070.
- Полная совместимость с AMD и выбор оптимального backend для разных GPU ещё требуют проверки.

Для VR не используется CPU-фильтр `v360` и не добавляется `hwdownload` ради перепроекции. Небольшая нагрузка на CPU при воспроизведении нормальна.

## VR: чистое превью для реставрации

Базовый режим VR должен показывать исходник без дополнительных реставрационных шейдеров, шумоподавления, повышения резкости и нейросетевого апскейла. Единственное необходимое преобразование — VR → flat, чтобы удобно оценивать изображение на обычном мониторе.

Технически сама перепроекция выполнена шейдером `shaders/vr-flat.glsl`. Поэтому «без шейдеров» в контексте flat-превью означает **без дополнительных шейдеров улучшения**, а не отключение перепроекции. Цветовое преобразование и обычное масштабирование рендерера также остаются необходимыми; это не побитовая копия исходника.

### Автоматический выбор

VR-автоопределение разрешено **только для файлов с расширением `.mp4`**, без учёта регистра. Остальные расширения воспроизводятся без автоматического включения VR и без вызова ffprobe.

При открытии локального MP4 скрипт:

1. Асинхронно вызывает ffprobe и ожидает результат перед началом воспроизведения.
2. Проверяет метаданные сферической проекции и стереораскладки.
3. Если поддерживаемых метаданных нет, использует маркеры в имени файла.
4. Если определить VR нельзя, выбирает обычное воспроизведение.

Таймаут ffprobe — 10 секунд. При ошибке или отсутствии ffprobe остаётся определение по имени. Сетевые входы не передаются ffprobe; для подходящих имён сохраняется запасной разбор названия.

Поддерживаются `Spherical Mapping`, `Stereo 3D`, а также теги `projection`/`vr_projection`, `stereo_mode`/`stereo_layout`, `vr_fov`/`id_fov`. Неподдерживаемые проекции, сферический crop и поворот не угадываются. Fisheye требует явно заданных 190°/200° и SBS. Разрешение само по себе не доказывает тип VR.

| Обозначение в имени | Интерпретация |
| --- | --- |
| `180_3dv`, `180_TB`, `180_OU` | VR180, глаза сверху/снизу |
| `360_OU`, `360_TB`, `360_3dv` | VR360, глаза сверху/снизу |
| `180_3dh`, `180_SBS`, `VR180_SBS_LR` | VR180, глаза рядом |
| `360_3dh`, `360_SBS` | VR360, глаза рядом |
| `fisheye200`, `mkx200` | Fisheye 200°, SBS |
| `fisheye`, `mkx` | Запасной вариант fisheye 190°, SBS |

По метаданным также поддерживаются 180°/360° mono. Выбирается первый глаз в раскладке; для SBS LR это левый, для TB — верхний.

В консоли отображается основание выбора:

```text
VR detection: 360-sbs (metadata)
VR detection: vr180 (filename; no usable VR metadata)
VR detection: none (non-MP4 input; VR disabled)
```

Проверенные файлы, предоставленные пользователем, с маркерами `180_3dv`, `360_OU` и `180_180x180_3dh_LR` не содержат VR-метаданных. Для них работает запасной разбор имени.

### Управление и скриншоты

| Действие | Управление |
| --- | --- |
| Поворот VR-камеры | Удерживать `Alt + ЛКМ` и двигать мышь |
| Вернуть взгляд в центр | `Ctrl + Backspace` |
| Полный экран | Двойной щелчок ЛКМ |
| Скриншот с GPU-перепроекцией | `Ctrl + S` (`screenshot window`) |
| Обычный скриншот до GPU-шейдеров | `s` / `Shift + S` |

VR-привязки включаются только при активном шейдере перепроекции. Для обычных видео сохраняются обычные привязки, включая `Alt + ЛКМ` для pan.

Скриншоты сохраняются в PNG в `~/Downloads`. WebP-кодировщик текущей сборки mpv не открывается; PNG проверен. Скриншот окна отражает выбранный ракурс и масштаб вывода, а не исходное разрешение полного VR-кадра.

## Рабочий процесс реставрации

1. Открыть VR-видео в чистом flat-превью.
2. Выбрать ракурс и проблемные фрагменты: шум, блоки, banding, недостаток деталей, ringing.
3. Вручную подобрать цветовые параметры, deband, шумоподавление, повышение резкости и апскейл.
4. Сравнить обработку с исходником, проверить несколько сцен и отсутствие артефактов.
5. Зафиксировать параметры в воспроизводимой команде или профиле.
6. Применить проверенную цепочку к полному видео и сохранить результат.

Нужно различать **flat-превью одного глаза** и **реставрацию исходного полного SBS/TB-кадра**. Экспорт flat-ракурса не сохраняет полный VR-источник и его стереоскопию.

### Пример ручного подбора, cmd.exe

Пример параметров пользователя; качество и скорость нужно оценивать на конкретном источнике. Автопрофили отключены, поэтому VR → flat здесь автоматически не включается. Это просмотр полного исходного кадра с явно заданной реставрационной цепочкой.

```cmd
set "SOURCE=X:\Path\To\Video.mp4"
mpv --load-auto-profiles=no "%SOURCE%" ^
  --brightness=0 --contrast=0 --saturation=-15 --gamma=0 --hue=-5 ^
  --scale=ewa_lanczos --scale-antiring=0.3 ^
  --cscale=ewa_lanczos --cscale-antiring=0.3 --dscale=mitchell ^
  --correct-downscaling=yes --linear-downscaling=no ^
  --deband=yes --deband-iterations=3 --deband-threshold=32 --deband-range=16 --deband-grain=16 ^
  --glsl-shaders-clr ^
  --glsl-shaders="~~/shaders/nlmeans.glsl;~~/shaders/FSRCNNX/FSRCNNX_x2_16-0-4-1_enhance.glsl;~~/shaders/adaptive-sharpen.glsl;~~/shaders/SSim/SSimDownscaler.glsl" ^
  --video-sync=audio
```

Отключение `load-auto-profiles` отключает именно условные профили, но не пользовательские Lua-скрипты. Для ручной настройки flat-превью понадобится явно включить подходящий VR-профиль и включить `vr-flat.glsl` в нужном месте цепочки; очистка `glsl-shaders` удаляет и перепроекцию.

### Обратный захват и кодирование: рабочий сценарий пользователя

Пользователь проверил свою полную команду mpv → rawvideo/NUT → FFmpeg → NVENC и подтвердил, что эффект реставрации присутствует в итоговом видео. Это рабочая отправная точка проекта; не нужно отказываться от неё только ради более тяжёлых и медленных моделей. По опыту пользователя, Topaz и Real Video Enhancer слишком медленны для его задачи.

При этом вклад каждого конкретного GLSL-шейдера ещё не изолирован независимым A/B-тестом. Подтверждение видимого эффекта и доказательство экспорта всей цепочки — разные уровни проверки.

Схема транспорта и кодирования после подбора параметров:

```cmd
set "OUTPUT=X:\Path\To\Video-restored.mp4"
mpv --load-auto-profiles=no "%SOURCE%" --o=- --of=nut --ovc=rawvideo --oac=pcm_s16le | ffmpeg -n -init_hw_device cuda=cuda:0 -filter_hw_device cuda -i pipe:0 -i "%SOURCE%" -map 0:v -map 1:a? -vf "hwupload,scale_cuda=4800:2400" -c:v hevc_nvenc -rc constqp -qp 18 -b:v 0 -c:a copy "%OUTPUT%"
```

Здесь намеренно не повторена вся цепочка реставрации: это сокращённая схема транспорта и кодирования, а не полная команда пользователя. Для рабочего прогона нужны выбранные и проверенные параметры обработки. Используется `-n`, а не `-y`, чтобы не перезаписать существующий файл; вход и выход должны иметь разные пути.

Критические ограничения:

- Режим кодирования mpv `--o` не является захватом окна `gpu-next`. Нельзя считать, что `--glsl-shaders`, GPU-deband, GPU-масштабирование и экранная цветокоррекция автоматически попадут в выходной поток.
- Проверено экспериментально: `--glsl-shaders` и vo-настройки (`brightness`, `deband`, `scale`) через `--o` не экспортируются — rawvideo из pipe остаётся исходного размера и без обработки. Эффект в раннем тесте давал `scale_cuda` ffmpeg.
- **Рабочий путь экспорта GLSL-обработки:** `--vf=gpu` (offscreen-контекст vo_gpu как фильтр, тот же `--glsl-shaders` применяется). Его опции `w`/`h` задают размер выхода фильтра; чтобы `WHEN`-условия апскейлеров (FSRCNNX и др.) сработали, выход должен превышать источник минимум ~в 1.2 раза. Затем ffmpeg `scale_cuda` приводит к целевому размеру.
- Ограничения `vf=gpu`: статус experimental, RGB→yuv420p конвертируется на CPU, OSD рендерится софтверно, при одновременном `--vo=gpu` фильтрация задваивается.
- CUDA/NVENC — путь NVIDIA. Для AMD нужен отдельный совместимый вариант обработки и аппаратного кодирования, например с AMF там, где он доступен.
- Пайп rawvideo через CPU не гарантирует zero-copy: возможны большие расходы на передачу кадров и последующий `hwupload`.
- `scale_cuda` поддерживает не все входные пиксельные форматы; преобразования нужно проверить отдельно.
- Размер 4800×2400 подходит выбранному примеру, но не универсален для TB, mono и других раскладок.
- Нужно проверить синхронизацию и длительность при копировании аудио из второго входа, а также сохранность HDR, цветовых и VR-метаданных.
- Бинарный pipe следует проверять в `cmd.exe` или подходящей современной оболочке; Windows PowerShell 5.1 не следует использовать для такого транспорта без отдельной проверки.

## Конечная цель: XBVR → DeoVR на Quest 2

Результат обработки — полноценное стереоскопическое VR-видео для библиотеки XBVR и воспроизведения в DeoVR на Meta Quest 2. Важно сохранить исходную проекцию, оба глаза, порядок глаз, частоту кадров и синхронизацию звука. Flat-ракурс нужен для настройки на ПК, а не как замена полного VR-файла.

Критерии успеха: заметное улучшение в шлеме, стабильное воспроизведение и достаточная скорость обработки библиотеки. Максимальное разрешение само по себе не является целью.

### Оценка выбранного подхода

- Компактный нейросетевой апскейл FSRCNNX и аппаратное кодирование — перспективный компромисс между качеством и скоростью. FSRCNNX не является универсальной моделью видеореставрации и не гарантирует восстановление утраченных деталей.
- Контролировать сглаживание текстур шумоподавлением, ореолы от резкости, усиление блоков, мерцание и нестабильность деталей в движении.
- Проверить необходимость каждого масштабирования: увеличение FSRCNNX, уменьшение и дополнительный scale_cuda могут быть полезны, но лишние проходы не гарантируют улучшения.
- Проверить обработку глаз с изоляцией их границ: фильтры не должны смешивать изображения SBS/TB.
- HEVC/NVENC — основной кандидат для NVIDIA; QP 18 — отправная точка, а не универсальный оптимум. Проверять размер, пиковый битрейт и совместимость конкретного разрешения/fps на Quest 2.
- Проверять прямое воспроизведение через XBVR/DeoVR без дополнительного перекодирования и пропускную способность сети.
- Окончательное решение принимать по движущемуся изображению в Quest 2, а не только по скриншотам на мониторе.

### Следующий эксперимент

Сравнить один и тот же короткий фрагмент в четырёх вариантах:

1. Исходник.
2. Только масштабирование и кодирование.
3. Те же параметры выхода с добавленным FSRCNNX.
4. Полная реставрационная цепочка.

Для вариантов 2–4 сохранить одинаковые разрешение, fps и настройки кодирования. Зафиксировать время обработки, скорость в fps, размер и битрейт, артефакты и субъективный результат в DeoVR. Это проверит вклад FSRCNNX в экспорт и пользу полной обработки. Затем подобрать несколько умеренных пресетов по типу исходника вместо одного агрессивного универсального.

Готовый скрипт прогона: `tools\vr-ab-test.bat` (только cmd.exe; переменные SRC/OUTDIR/START/END/WIDTH/QP сверху; сегмент и высоты 2400/2402/2404 для быстрого различия файлов в DeoVR).

## Репозиторий

Корень Git-репозитория — каталог `portable_config`, не каталог с mpv.exe. Исходные конфиги, Lua-скрипты, GLSL-шейдеры и документация предназначены для версионирования.

`.gitignore` исключает кэш, историю просмотров, позиции воспроизведения, логи, временные файлы, резервные копии, медиа, результаты обработки, исполняемые файлы и персональные шрифты NetflixSans/TX-02. Нужные ресурсы интерфейса uosc остаются в составе исходников. Игнорирование не удаляет локальные файлы.

Клонирование пока не заменяет установщик: mpv/FFmpeg и необходимые бинарные зависимости, включая `scripts/uosc/bin/ziggy-windows.exe`, нужно предоставлять отдельно. До публикации проверить лицензии сторонних скриптов, шейдеров и ресурсов; локальное наличие файла не означает право на его распространение. Личные пути в новых примерах заменять на нейтральные.

## Дальнейшее развитие

### Аппаратные backend и качество

- Проверить NVIDIA и AMD на разных кодеках, разрешениях, HDR и разрядностях.
- Определить надёжную стратегию выбора Vulkan / D3D11VA и fallback.
- Разделить чистое превью, интерактивную реставрацию и offline-обработку.
- Проверить экспорт именно обработанного изображения, а не только декодированного исходника.

### VSR

- Исследовать включение VSR при воспроизведении, требования к драйверам и совместимым GPU/backend.
- Проверить результат и ограничения на VR, HDR и разных разрешениях.
- Измерить качество, плавность и нагрузку; не смешивать VSR с базовым чистым VR-превью.

`vr_vsr.conf` уже существует как экспериментальный файл, но не подключён в `mpv.conf` и не считается проверенной реализацией. `vr_rst.conf` также не подключён по умолчанию.

### Установщик / обновление

- Создать установщик или bootstrapper, который скачивает последнюю подходящую сборку mpv и весь конфиг.
- Определить доверенный источник сборок и проверку целостности загрузок.
- Сохранять portable-структуру, подтягивать скрипты, шейдеры, шрифты и нужные зависимости.
- Предусмотреть обновление без потери пользовательских настроек, резервные копии и откат.
- Фиксировать версии для воспроизводимости и тестировать совместимость перед заменой рабочей сборки.

## Проверка изменений

Короткая проверка воспроизведения без звука и автоплейлиста:

```cmd
mpv "X:\Path\To\Video.mp4" --frames=5 --no-audio --keep-open=no --autocreate-playlist=no --save-position-on-quit=no
```

Проверять сообщение VR detection, выбор профиля, строку аппаратного декодирования и отсутствие ошибок шейдера/фильтров. Для изменений автопрофилей дополнительно проверять переходы VR → VR другого типа → обычное видео. Короткий запуск не заменяет визуальную оценку и длительную проверку производительности.

Включённые сторонние компоненты (шейдеры, Lua-скрипты, шрифты uosc) остаются под **своими лицензиями**: MIT, LGPL-2.1/3.0+, GPL-2.0/3.0, MPL-2.0, BSD-2-Clause — авторские заголовки в файлах сохраняются и являются обязательной атрибуцией. Полный список компонентов, источников и лицензий: `THIRD_PARTY.md`.

Компоненты без явной лицензии у апстрима помечены как unverified — до подтверждения их повторное распространение следует считать ограниченным. Бинарник mpv (GPL-2.0+/LGPL-2.1+) репозиторием не распространяется; установщик должен скачивать его из официального источника.
